# Entwicklungsregeln
Verbindliche Spezifikation: docs/REQUIREMENTS.md, ARCHITECTURE.md, ROADMAP.md, TEST_STRATEGY.md, DECISIONS.md. Abweichungen dokumentieren und bei fachlichen Änderungen Freigabe einholen. Feature-Branch und Pull Request je Meilenstein. Nach bestandenen Prüfungen und bei erfüllten Branch-Schutzregeln den Pull Request eigenständig in den Zielbranch mergen. Abhängige Pull Requests bei Bedarf zuerst umstellen. Den vollständig integrierten Entwicklungsbranch anschließend auf GitHub und lokal löschen. Keine Geheimnisse, personenbezogenen Daten oder nicht lizenzierte Assets committen. Tests lokal ausführen, CI-Ergebnisse prüfen, tatsächliche Resultate und Blocker im PR dokumentieren. Keine erfundenen Testresultate. Lockfile pflegen, Version/Changelog aktualisieren. Keine Cloud- oder Tracking-Abhängigkeiten. Datenverlust durch Updates verhindern.
